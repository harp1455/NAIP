# NAIP

NovelAI 이미지 대량 출력용 안드로이드 앱. [NAIS3](https://github.com/sunanakgo/NAIS3)의 요청 조립·비용 계산·전처리
로직을 기반으로, 모바일 화면에 맞춰 다시 만든 개인용 비공식 클라이언트입니다.

## 기능

- **생성 중 미리보기**: generate-image-stream(msgpack)으로 그리는 과정을 단계별로 보여 줍니다(설정에서 끌 수 있음).
  중간 그림은 저장하지 않고, 화면이 꺼져 있으면 그리지 않습니다. 응답을 받기 시작한 뒤 끊긴 장은 이미 과금됐을 수 있어 자동으로 다시 요청하지 않습니다.
- **대량 생성**: N장을 설정해도 서버에는 항상 1장(`n_samples: 1`)씩 N번 순서대로 요청합니다.
  생성 중에 + 단추로 그 순간의 설정을 대기열에 넣어 이어서 돌릴 수 있고, 진행 알림의 "중지"로 바로 멈출 수 있습니다.
  한 장이 끝나면 설정한 범위(1.0~2.0초, 0.1초 단위의 최소·최대)에서 무작위로 쉰 뒤 다음 장을 요청합니다.
  앱을 뒤로 보내거나 화면을 꺼도 포그라운드 서비스로 계속 진행하고, 진행·완료 알림과 완료 진동을 줍니다.
  대기열과 진행 상황은 기기에 저장돼, 앱이 꺼졌다 다시 열리면 이어서 생성할지 묻습니다. 요청을 보낸 뒤 결과를 받기 전에
  꺼진 장은 이미 과금됐을 수 있어 "확인 필요"로 표시하고, 직접 고르지 않는 한 다시 요청하지 않습니다.
- **프롬프트**: 고정 / 가변 / 디테일 3분할 + 네거티브, 프롬프트 프리셋(복제 가능).
  쓴 토큰 수 / 한도를 모델에 맞는 토크나이저로 표시합니다 (V4·V4.5는 T5 512, V5 Full은 Qwen 1471, V5 Curated는 703).
  칸마다 클립보드 붙여넣기·비우기(되돌리기) 버튼이 있습니다.
- **가중치 색상**: 강조(`1.2::…::`, `{…}`)는 빨강, 약화(`0.7::…::`, `[…]`)는 파랑, 음수(`-1::…::`)는 보라,
  조각은 초록, 주석 줄은 회색 배경으로 표시합니다. 가중치가 1에서 멀수록 진해집니다.
- **태그 자동완성**: 단부루(약 17만 개)·e621(약 11.6만 개) 태그를 정확도 순(완전 일치 → 앞부분 → 단어 시작 → 포함,
  같은 단계는 게시물 수 순)으로 키보드 위에 제안합니다. 내가 자주 고른 태그는 맨 앞(★)에 나옵니다. 출처는 전체/단부루/e621로 바꿀 수 있고, 한국어 키워드로도 찾습니다.
- **조각(와일드카드)**: `<이름>`, `<폴더/이름>`, `<*이름>`(순차), `<a|b|c>`, `(a, b/c)`, `a/b/c`. 장마다 새로 뽑습니다.
- **씬**: 장면별 프롬프트(+네거티브·해상도·씬별 출연 캐릭터)를 묶음으로 관리하고, 씬마다 장수를 예약해 한 번에 생성.
  만든 이미지는 씬별로 모아 보고, 갤러리에도 씬 이름 폴더로 나눠 저장합니다.
- **캐릭터**: 캐릭터를 라이브러리에 추가·복제하고 폴더로 관리. 캐릭터 프롬프트는 고정(얼굴·체형·머리) / 가변 / 디테일 + 네거티브로
  나누고, 변형 그룹(복장·표정·자세·행동·액세서리·사용자 정의)마다 항목을 고정·무작위(비중)·순차·미사용으로 고릅니다.
  보내는 캡션은 고정, 고른 변형, 가변, 디테일 순서이고 항목 안의 조각 문법도 그대로 씁니다.
- **출연 슬롯**: 출연 자리마다 고정 / 무작위(캐릭터·폴더 후보, 후보별 비중) / 순차(한 바퀴 뒤 처음부터 또는 비움) / 확률(예: 30%) / 비활성.
  같은 캐릭터 중복 허용, 장마다 또는 배치에 한 번 뽑기, 씬마다 따로 뽑기, "이번 장 예시" 미리보기.
  메인 프롬프트의 인원 태그(2girls·solo 등)가 실제 인원과 다르면 알리고, 켜 두면 고쳐 보냅니다. 모델 한도(V4·V4.5 6명, V5 32명)를 넘는 캐릭터는 알리고 뺍니다.
  위치는 슬롯마다 배치 판에서 마커를 끌어 정합니다 — V5는 자유 위치(0.1%), V4·V4.5는 5×5 격자.
  고르게 배치·좌우 반전·모두 AI, 씬별 위치 저장. 대기열 배치는 누른 순간의 캐릭터 내용으로 돕니다.
- **i2i / 인페인트**: 갤러리·히스토리 이미지를 원본으로. 마스크 편집기는 두 손가락 확대·이동(최대 16배), 1px부터 숫자로 정하는
  브러시, 지우개, 제한 없는 되돌리기/다시 하기, 전체·해제·반전, 8px 확장·축소, 색·투명도, 원본 비교, 마스크 보관·불러오기를
  지원합니다. 인페인트 결과를 다시 고치면 같은 크기에서는 마스크가 유지되고, 결과에는 원본 그림이 기록됩니다(편집 계보).
- **바이브 트랜스퍼**: 인코딩 결과를 모델·정보 추출값별로 캐시, `.naiv4vibe` 파일 가져오기.
- **정밀 레퍼런스**: V4.5는 캐릭터 / 스타일 / 캐릭터+스타일 + 강도·충실도. V5 Full·Curated는 의상 레퍼런스,
  "같은 의상 선호", 강도 0~5(충실도 없음)를 지원하고 이미지를 V5 크기 표에 맞춰 보냅니다. V5 Medium·V4와
  V5 인페인트에서는 보내지 않습니다. 레퍼런스 복제·이름 변경·모두 켜기/끄기, 히스토리 이미지를 레퍼런스·바이브로 보내기.
- **디렉터 툴 · 업스케일**: 배경 제거, 선화, 스케치, 채색, 표정, 정리, 2배 업스케일. 결과에 이어서 다른 도구 적용 가능.
- **복사·공유**: 결과·히스토리·이미지 화면에서 그림을 꾹 누르거나 복사 단추로 클립보드에 복사(메신저에 바로 붙여 넣기),
  여러 장 공유, 복사·공유할 때 메타데이터 지우기 설정.
- **히스토리**: 프롬프트·캐릭터·씬·시드 검색(쉼표로 여러 단어), 즐겨찾기, 미저장만 보기, 씬별 보기, 두 손가락 확대·이동(두 번 탭으로도 확대), 여러 장 선택 삭제, 보관 한도, 자동 저장, 공유.
  기록은 SQLite, 원본·썸네일은 앱 전용 폴더의 파일로 보관하고 화면에 보이는 칸만 그려 수만 장도 바로 열립니다.
  설정 → 저장 공간에서 앱이 쓰는 용량·캐시·갤러리 저장 수를 보고, 기록과 파일이 맞는지 점검하고(고르기 전에는 지우지 않음) 캐시를 비울 수 있습니다.
  공간이 부족하면 생성 전에 알려 줍니다.
- **골라서 저장**: 히스토리에서 고른 그림만 `Pictures/NAIP/폴더`에 저장. 폴더를 새로 만들 수 있고, 파일 이름은 자동(이름_01, 이름_02 … 같은 폴더에서는
  번호를 이어 매김, 이름을 비우면 날짜·시드)과 하나씩 지정 중에서 고르며, NAI 메타데이터(텍스트 청크 + 알파 채널 스텔스 정보)를 남길지
  지울지 고릅니다. 저장한 그림에는 "저장됨" 표시가 붙습니다.
- **다시 생성 · 재추첨 생성**: 히스토리 이미지를 그때와 같은 내용·새 시드로 한 장 더 (화면의 프롬프트·레퍼런스는 건드리지 않음).
  재추첨은 그 이미지의 슬롯·변형 설정(당시 캐릭터 원문)으로 출연·변형·조각을 다시 뽑습니다.
- **바이브 복원**: NAI 이미지에 들어 있는 인코딩된 바이브를 원본 그림 없이 되살립니다 (설정 불러오기에서 선택).
- **설정 불러오기**: NAI 이미지의 메타데이터나 히스토리 이미지에서 프롬프트·네거티브·캐릭터·모델·해상도·샘플링·시드를
  항목별로 골라 불러오고, 새 프리셋으로 저장할 수 있습니다.
- Opus의 V5 할당량을 퍼센트와 막대로 표시(생성할 때마다 갱신, 충전 속도·부스트 표시).
- 보유 Anlas와 예상 사용량, 남은 시간 표시, 429·5xx 자동 재시도, 백업 내보내기/불러오기.

## 설치 · 업데이트

`Build APK` GitHub Actions 워크플로가 푸시마다 디버그 APK를 빌드하고, 커밋 메시지에 `[release]`가 있을 때만 **릴리스**(`build-번호`)로 올립니다.
처음 한 번만 [Releases](../../releases/latest)에서 APK를 내려받아 설치하세요 (Android 10 이상).

그다음부터는 앱이 열릴 때마다 최신 릴리스를 확인하고, 새 빌드가 있으면 화면 위에 "업데이트" 버튼을 띄웁니다.
누르면 앱이 APK를 내려받아 설치 화면까지 열어 줍니다 (설정 탭 → 앱 업데이트에서도 확인 가능).
서명 키가 저장소에 고정돼 있어 덮어써도 데이터가 유지됩니다.

저장소를 비공개로 바꾼 뒤에는 설정 탭 → 앱 업데이트 → "비공개 저장소용 토큰"에 이 저장소의 Contents 읽기 권한만 준
fine-grained 토큰을 넣어야 확인·다운로드가 됩니다.

앱 → 설정 탭에서 NovelAI Persistent API Token(`pst-…`)을 입력합니다.

## 개발

```sh
npm install
npm run dev        # 브라우저에서 UI 개발 (NAI API는 CORS를 허용하므로 그대로 호출됨)
npm test           # 단위 테스트
npm run apk        # 웹 빌드 → cap sync → android/app/build/outputs/apk/debug/app-debug.apk
```

APK 빌드에는 JDK 21과 Android SDK(platform 35)가 필요합니다 (`ANDROID_HOME` 지정).

구조: `src/nai/`(NAIS3에서 이식한 payload·모델·프리셋·Anlas·토크나이저), `src/stores/`(zustand 상태와 생성 큐),
`src/storage/`(히스토리·대기열 저장소: SQL 계층, 파일 보관, 스키마, 예전 IndexedDB 옮기기), `src/components/`(화면),
`android/`(Capacitor 프로젝트 + 갤러리 저장/화면 켜짐 유지 플러그인, SQLite·파일 저장소 플러그인).
브라우저 개발 빌드와 테스트는 같은 SQL을 sql.js(WASM)로 실행합니다.

## 알아 둘 점

- 이전 버전에서 업데이트하면 처음 한 번 히스토리를 새 저장소로 옮깁니다(진행 화면 표시). 모두 옮기고 장수와 파일 크기를
  확인한 뒤에만 예전 데이터를 지우고, 중간에 꺼져도 다음에 이어서 합니다. 옮기는 동안 히스토리 크기만큼 빈 공간이 더 필요합니다.

- 생성은 웹뷰 안에서 돌고, 백그라운드에서는 포그라운드 서비스가 프로세스를 붙잡아 둡니다.
  제조사 배터리 최적화가 강한 기기에서는 그래도 멈출 수 있으니, 그럴 때는 앱의 배터리 사용을 "제한 없음"으로 바꾸세요.
- 조각 문법은 NAIS3와 같아서 `red/blue`처럼 공백 없는 슬래시 태그도 선택지로 취급합니다.
- 자동완성 데이터(`public/tags/`)는 `scripts/build-tags.py`로 다시 만들 수 있습니다
  (단부루: NAIS3 `tags.json`, e621: 공식 db export, 한국어 키워드: NAIA2.0 데이터).
