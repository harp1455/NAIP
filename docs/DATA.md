# 데이터 · 호환성

NAIP가 무엇을 어디에 저장하는지, 버전을 올리거나 내릴 때·백업을 옮길 때 무엇이 유지되는지 정리한 문서입니다.

## 어디에 저장되나

| 데이터 | 위치 | 비고 |
|---|---|---|
| 히스토리 기록 | 앱 전용 `databases/naip-history.db` (SQLite, WAL) | 0.13.0부터. 그 전에는 웹뷰 IndexedDB |
| 히스토리 원본·썸네일 | 앱 전용 `files/images/<id>.png·webp`, `files/thumbs/<id>.jpg` | 앱을 지우면 함께 지워집니다 |
| 대기열(이어서 생성용) | 앱 전용 `files/queue/<배치>.json` + DB의 진행 행·뽑기 상태(`app_kv`의 `queue-draw:<배치>`) | 끝난 배치는 지웁니다 |
| 복원 전 자동 백업 | 앱 전용 `files/backups/` | 최근 3개만 둡니다 |
| 프롬프트·프리셋·캐릭터·씬·조각·설정·프로젝트 | 웹뷰 localStorage (`naip-*`) | |
| 바이브·레퍼런스·마스크 | 웹뷰 IndexedDB `kv` | |
| NovelAI·GitHub 토큰 | Android Keystore(AES-256-GCM, 토큰마다 따로 만든 키)로 암호화한 앱 전용 설정 | 0.13.0부터. 백업에도 기기 간 전송에도 넣지 않습니다(키가 기기를 떠나지 않아 새 기기에서는 토큰을 다시 넣습니다) |
| 갤러리에 저장한 그림 | `Pictures/NAIP/…` (MediaStore) | 앱을 지워도 남습니다 |
| 프로젝트 내보내기 목록(CSV 등) | `Download/NAIP/…` | Android가 Pictures 아래에 텍스트 파일을 허용하지 않아서 |

## 0.12.0 → 0.13.0 업데이트 때 바뀌는 것

- **히스토리 옮기기**: 처음 실행하면 IndexedDB의 히스토리를 SQLite + 파일로 옮깁니다(진행 화면).
  - 빈 공간을 먼저 확인합니다. 모자라면 필요한 양을 보여 주고 "나중에"를 고를 수 있습니다(설정 → 저장 공간에서 다시 시작).
  - 한 장씩 파일을 쓰고 크기를 확인한 뒤 기록을 넣습니다. 중간에 꺼지면 다음 실행에서 이어서 합니다.
  - 장수와 모든 파일 크기를 확인한 **뒤에만** 예전 히스토리 저장소를 비웁니다. 바이브·레퍼런스·마스크(`kv`)는 건드리지 않습니다.
  - 옮기는 동안 히스토리 크기만큼 빈 공간이 더 필요합니다.
  - 예전 저장소에서 읽을 수 없는 원본이 있으면 나머지를 모두 옮긴 뒤 멈춥니다(예전 데이터는 그대로). "읽을 수 없는 N장은 건너뛰고 마치기"를
    확인해야만 그 장을 원본 없는 기록(썸네일·생성 정보는 남김)으로 넣고, 나머지를 한 번 더 확인한 뒤 예전 저장소를 비웁니다.
  - 옮기기가 끝나기 전에 지운 그림은 예전 저장소에서도 지워, 다음 실행 때 다시 옮겨 오지 않습니다.
- **캐릭터**: 예전 캐릭터 프롬프트 한 칸은 "고정"으로 옮기고 가변·디테일은 비워 둡니다. 예전 출연 목록은 같은 순서의 고정 슬롯이 됩니다(켜짐·위치 유지).
- **토큰**: 예전에 설정에 평문으로 있던 토큰은 첫 실행 때 Keystore로 옮기고 평문을 지웁니다.

## 이전 버전으로 돌아가기

- 코드 기준점: GitHub 릴리스 **`build-18`** (0.12.0, 커밋 `bb17170`)이 이번 작업 직전 릴리스입니다.
- Android는 더 낮은 버전을 덮어 설치하지 못하므로, 되돌리려면 앱을 지우고(앱 안 데이터도 함께 지워짐) 옛 APK를 설치해야 합니다.
- 0.12.0은 새 백업 파일(`.naipbackup`)과 새 히스토리 저장소를 읽지 못합니다. 돌아갈 가능성이 있다면 **업데이트 전에**
  0.12.0의 설정 → 백업(JSON)으로 프롬프트·프리셋·캐릭터·조각·씬을 내보내고, 남길 그림은 갤러리에 저장해 두세요.
  0.13.0은 그 JSON 백업을 그대로 불러올 수 있습니다(캐릭터는 새 구조로 옮겨짐).

## 백업 파일 (`.naipbackup`)

ZIP 파일입니다. 설정 → 백업·복원에서 만들고 불러옵니다.

- `manifest.json` — 형식 이름(`NAIP`), 형식 버전, 앱 버전, 만든 시각, 모드, 담은 항목과 개수
- `checksums.json` — 다른 모든 항목의 SHA-256과 크기
- `sections/<항목>.json` — 항목마다 하나. 바이브·레퍼런스·마스크 그림은 `assets/` 아래 파일로 따로 둡니다
- `history/meta-000001.jsonl` … — 히스토리 기록 500개씩
- `history/originals/<id>.<확장자>` — 원본 이미지(전체 백업 또는 직접 골랐을 때)

**모드**
- 가벼운 백업: 설정, 작업 중 프롬프트, 프리셋, 캐릭터, 씬, 조각, 바이브, 정밀 레퍼런스, 태그 사용 기록, 마스크, 저장 폴더, 프로젝트. 히스토리는 없음
- 전체 백업: 위 + 히스토리 기록 + 원본 이미지
- 직접 고르기: 항목별 선택. "히스토리 기록(썸네일)"과 "원본 이미지"를 따로 고르며, 원본을 고르면 기록도 함께 담깁니다

**항상 빠지는 것**
- NovelAI·GitHub 토큰과 이름이 token·secret·password·apiKey·credential·cookie로 끝나는 값, `pst-…`·GitHub 토큰·`Bearer …` 모양의 값 (쓸 때와 읽을 때 모두 지움)
- 생성 대기열 (그림 데이터가 들어 있고, 되살리면 의도치 않게 유료 생성이 돌 수 있어서)
- 앱 업데이트를 받을 저장소 설정 (백업 파일로 업데이트 출처를 바꾸지 못하게)

**읽을 때 확인하는 것**
- 더 새로운 형식 버전이면 "앱을 업데이트하세요"로 멈춥니다
- 체크섬이 맞지 않는 항목은 건너뛰고 무엇이 손상됐는지 보여 줍니다
- 목록이 없거나 목록이 아닌 항목은 "형식이 잘못됨"으로 건너뜁니다. 목록 안의 엉뚱한 값(빈 값·숫자 등)은 빼고 몇 개를 뺐는지 알려 줍니다
- 압축 경로 공격(절대 경로, `..`, 역슬래시, 제어 문자), 압축 폭탄(항목 수·크기·압축률 한도), 중복·암호화 항목은 거부합니다

**복원 방식**
- 덮어쓰기 / 합치기 / 항목 골라서. 합칠 때 id가 겹치는 캐릭터·씬 등은 새 id를 받고, 슬롯·후보·프로젝트 캐릭터의 참조도 따라 바꿉니다
- 히스토리: 건너뛰기 / 합치기(같은 id는 건너뜀) / 바꾸기
  - "바꾸기"도 지금 기록을 먼저 지우지 않습니다. 백업 기록을 모두 넣은 뒤, 손상·실패가 하나도 없을 때만 백업에 없던 지금 기록을 지웁니다
- 덮어쓰거나 바꾸기 전에는 지금 상태를 가벼운 백업으로 앱 안에 자동 저장하고(기본 켜짐), 결과 화면의 "복원 전으로 되돌리기"로 돌아갈 수 있습니다
- 복원해도 이 기기의 토큰은 바뀌지 않습니다
- 이 실행에서 바이브·레퍼런스·마스크를 불러오지 못했다면 그 항목은 백업에 넣지 않고(알림 표시), 복원할 때도 그쪽 연결을 끊지 않고 그대로 둡니다.
  그 실행에서 바꾼 바이브·레퍼런스·마스크는 저장하지 않으며, 앱을 다시 열면 저장된 것을 다시 불러옵니다

## 예전 백업 · NAIS3

| 불러올 수 있는 파일 | 처리 |
|---|---|
| NAIP 0.12.0 이하의 JSON 백업 | 같은 미리보기·복원 흐름으로. 캐릭터는 새 구조로 옮김 |
| NAIS3 `.nais` | 캐릭터·폴더, 프롬프트 프리셋, 조각, 씬, 바이브(인코딩 포함), 정밀 레퍼런스, 작업 중 설정을 가져오고, 못 가져온 것을 보고서로 보여 줌 |
| NAIS3 예전 JSON 백업 | 위와 같음 |

NAIS3에서 가져오지 않는 것(보고서에 표시): 라이브러리 스택·이미지, 폴더 색·접힘, 캐릭터 썸네일, 바이브·레퍼런스 폴더, `delta` 레퍼런스, NAIS3 전용 설정(투명 배경 등), 씬 묶음의 캐릭터 지정(NAIS3가 생성에 쓰지 않는 예전 값 — 씬은 프롬프트 화면 출연을 따름).

**NAIS3로 내보내기(.nais)**: 내보내기 전에 잃는 것을 먼저 보여 줍니다 — 태그 사용 기록, 마스크, 앱 설정, 저장 폴더, 프로젝트,
무작위·순차·확률 슬롯과 변형 그룹(고정 항목만 프롬프트에 합쳐 넣음), 캐릭터별 위치, 씬 출연·위치, 모델별 추가 바이브 인코딩.
NAIS3는 파일에 들어 있는 표를 통째로 바꾸므로, 내용이 있는 항목만 담습니다.

## 에셋 프로젝트 데이터

- 프로젝트(축·값·제외·덮어쓰기·선별 표시·내보낸 경로·이미지 코드)는 localStorage `naip-projects`에 있고 백업의 "프로젝트" 항목에 담깁니다.
- 그림 자체는 히스토리에 있고, 히스토리 기록에 프로젝트 표시(`project`)가 붙습니다. 히스토리에서 그림을 지우면 프로젝트에서도 빠집니다.
- 히스토리 보관 한도로 정리할 때 프로젝트 그림(탈락 제외)은 지우지 않습니다. 그래서 프로젝트 그림이 많으면 히스토리가 한도를 넘을 수 있습니다.
- 앱이 갑자기 꺼져 프로젝트 기록이 저장되지 못해도, 다음 실행 때 히스토리의 프로젝트 표시를 보고 그림을 조합에 다시 넣습니다.
- 이미지 코드(A001 등)는 그림이 아니라 "조합 + 채택 칸"에 붙습니다. 채택 그림을 교체해도 코드와 파일 이름이 그대로라 채팅 프롬프트가 깨지지 않습니다.
- 프로젝트 데이터가 약 3MB를 넘으면 목록에 경고가 뜹니다(localStorage 한도).
